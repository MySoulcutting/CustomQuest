CustomQuest 任务插件 Wiki

CustomQuest 是一款基于 Paper 1.21.x 服务端、由 TabooLib 6.2.4（Kether 脚本引擎） 驱动的任务插件， 深度对接 MythicMobs 与 Citizens2：通过 Citizens NPC 对话接取任务，击杀 MythicMobs 怪物 / 提交物品完成任务， 通过 NPC 对话 Kether 执行扩展动作，并使用 NPC data 变量实现分支任务与分支对话。

版本说明：当前 CustomQuest 版本为 1.6.6，使用 Paper 1.21.1 API 编译， 已在 Paper 1.21.11 上验证启动与 SoulCore 导航；其他 1.21.x 版本仍需实服验证。

功能特性

Citizens2 对接 NPC data 分支对话 多项目标 对话内接取指令 Kether 动作 全息视图

  • Citizens2 识别 NPC id：每个 NPC 对话配置文件（dialogues/*.yml）通过 npc 字段绑定一个或多个 NPC id。
  • NPC data 分支任务 / 分支对话（玩家级数据）：对话分支支持 data= / data-value=（或列表写法）与 PAPI 变量条件， 当 NPC 的 data 值不同时显示不同对话，用于接取任务、推进剧情。 data 变量按玩家独立存储：每个玩家在同一 NPC 上有自己的 data 值，不同玩家可处于不同对话分支，互不影响。
  • SoulCore 交互式任务对话：支持对应客户端通道时显示独立 NPC 对话界面；未安装客户端时自动回退到可点击聊天。 两种入口共用玩家绑定、60 秒有效且一次性消费的安全会话。
  • 对话内接取任务指令：对话选项直接配置 accept-quest: <任务ID> 即可接取任务（无需写 Kether）， 并可配置 accept-data 在接取成功后自动设置 NPC data 变量推进剧情； Kether 写法 quest accept <任务ID> [data <key> <value>] 同样支持。
  • 条件达成与完成分离：击杀目标首次达成或物品在 NPC 成功提交时提示玩家，并执行 condition-commands； 任务不会自动结算，必须由显式指令或 NPC 提交动作完成。
  • NPC 原子提交：对话选项使用 submit-quest 实时校验进度，并可用 submit-items 覆盖该按钮实际扣除清单；物品任务仅在成功时一次性扣除背包物品， 随后的选项 Kether 只会在提交成功后执行，任务完成本身不修改 NPC data。
  • 接取任务不校验前置条件：任务门控（谁能看到接取选项）完全由对话分支的 data / PAPI 条件控制。
  • 任务类型 × 多项目标：
    • kill_mob —— 击杀 MythicMobs 怪物，可配置多个怪物目标、各自计数；
    • submit_item —— 提交物品，可配置多种物品；
    • describe —— 描述任务（无目标，仅展示），用于在全息视图（计分板）显示任务标题与内容， 只能通过 /cq quest complete 指令强制完成。
  • 任务追踪：config.yml 一键开关；SoulCore HUD 优先显示任务与实时进度，无客户端通道时回退右侧计分板。
  • Kether 动作：NPC 对话选项可执行 Kether 脚本，并提供 quest accept、npc data set 等自定义动作。

安装

  1. 将构建产物 build/libs/CustomQuest-1.6.6.jar 与必需的 PlaceholderAPI 放入 plugins/ 目录；
  2. 按功能选装 MythicMobs 与 Citizens；
  3. 启动服务器（首次启动会联网下载 TabooLib 模块，并生成默认配置与示例文件）；
  4. 按需编辑 plugins/CustomQuest/ 下的配置后执行 /cq reload。

全局配置 config.yml

autosave-seconds: 300        # 玩家数据自动保存间隔（秒）

scoreboard:                  # SoulCore HUD 与回退计分板总开关
  enabled: true            # 同时控制 HUD 和回退计分板
  title: "&6&l任务追踪"  # 仅影响回退计分板
  gap-lines: 1           # 仅影响回退计分板任务间距

支持 SoulCore 任务通道时优先显示客户端 HUD，否则使用原生右侧计分板回退。 每项任务的显示内容请在任务文件（quests/*.yml）里用 board-title / board-line 完全自定义。

任务追踪（SoulCore HUD / 回退计分板）

在 config.yml 中开启 scoreboard.enabled 后：

  • 玩家接取任务后，支持通道的 SoulCore 客户端显示 HUD；其他玩家回退到右侧计分板；
  • 多项目标逐条显示：多目标任务的每个目标都会单独显示一行进度 （如「已击杀 SkeletonKing 3/10」「已击杀 ZombieMinion 2/5」），默认不显示总进度汇总行；
  • 击杀类任务显示「已击杀 怪物名 当前数量/总需击杀数量」，击杀 MythicMobs 怪物后即时刷新；
  • 提交物品类任务显示「已收集 材料 当前数量/总需求」，进度随背包数量自动刷新；
  • 描述任务：计分板显示任务标题 + 任务内容（description 逐行展示），指令强制完成后移除；
  • 完成 / 放弃任务后对应条目即时移除，无任务时自动清空计分板；
  • 将开关改为 false 并执行 /cq reload 即可关闭，并自动清空本插件设置的计分板。

多目标显示效果示例

&6&l任务追踪
&e清剿荒野
 已击杀 SkeletonKing 3/10
 已击杀 ZombieMinion 2/5
计分板总行数受 Minecraft 侧边栏 15 行限制；每个任务按「完整块」显示（标题 + 全部目标进度行）， 放不下的任务整体跳过并以「…还有 N 个任务」提示。

显示内容自定义（格式变量）

计分板的显示内容不再在 config.yml 里配置，而是在任务文件里自定义： board-title（标题行）+ board-line（任意多行列表）。

完全自定义（推荐）

在任务文件里写 board-title（标题行）+ board-line（任意多行列表）， 即可完全控制该任务在计分板上的每一行，不再自动生成目标行。 

# quests/example_kill.yml —— 完全自定义
board-title: "&6&l{name}"
board-line:
  - "&7目标1：击杀 &f{display1} &e{current1}&7/&e{total1}"
  - "&7目标2：击杀 &f{display2} &e{current2}&7/&e{total2}"
  - "&7总进度：&e{current}&7/&e{total}"
变量说明
{name} / {id} / {type}任务名称 / ID / 类型显示名
{current} / {total}任务总进度 / 总需求（所有目标合计）
{targetN}第 N 个目标标识（击杀 = 怪物内部名；提交 = 材料名），N 从 1 开始
{displayN} / {mobN} / {itemN}第 N 个目标显示名
{currentN} / {totalN} / {amountN}第 N 个目标进度 / 需求 / 需求（同 totalN）

不写 board-line 时的自动模式

若任务文件里没有 board-line 列表，则按「标题 + 每个目标一行」自动生成； 此时可用 board-title 覆盖标题行、用目标里的 board-line 覆盖单个目标行。 

# quests/example_kill.yml —— 自动模式下的单行覆盖
board-title: "&6&l{name}"          # 可选：本任务标题行
objectives:
  - mob: SkeletonKing
    amount: 10
    board-line: "&c击杀 {target} &e{current}&7/&e{total}"  # 可选：本目标行
变量说明
{name} / {id} / {type}任务名称 / ID / 类型显示名
{target}目标标识（击杀 = MythicMobs 怪物内部名；提交 = 材料名）
{display}目标显示名（目标里自定义的 name，未填则为标识）
{mob}击杀目标的显示名
{item}收集目标的显示名
{current}当前进度（该目标的当前数量）
{total}总需求（该目标的需求数量）
{amount}目标需求数量（同 {total}）
{index}目标序号（从 1 开始）
{line}描述任务的单行内容（仅描述任务内容行可用）

格式支持 & 颜色代码与 PAPI 占位符；改完后执行 /cq reload 即时生效。

任务导航

在 SoulCore HUD 中点击任务的「导航」按钮后：

  • 需要客户端安装支持 soulcore:quest_navigation 通道的 SoulCore Fabric Mod；未安装时不会建立导航
  • Mod 在目标位置渲染原版信标材质光柱、圆环和随距离缩放的任务名/距离悬浮标签
  • 靠近目标（5 米内）提示到达并自动结束导航
  • 同一时间只能导航一个任务：导航第二个任务会自动取消第一个；再次点击按钮（显示为「取消导航」）取消导航
  • 全部视觉效果仅存在于客户端，不修改服务端方块、不生成实体；超过 Mod 世界标记范围时不显示导航视觉
# quests/example_kill.yml —— 导航位置配置
navigate: "world,100,64,200"   # 世界名,x,y,z

玩家可用 /cq nav <任务ID> 开始导航、/cq nav cancel 取消。 管理员可用以下指令写回任务位置（设为执行者当前位置）： /cq quest nav set <任务ID> / /cq quest nav remove <任务ID>

任务配置 quests/

一个任务对应一个 yml 文件，文件名任意，以 quest-id 为准。

类型一：击杀 MythicMobs 怪物（kill_mob，多目标）

quest-id: example_kill          # 任务 ID（全局唯一）
name: "&e清剿荒野"              # 任务名称（支持 & 颜色与 PAPI）
description:                     # 接取时显示的描述
  - "&7去清剿荒野上的怪物吧！"

type: kill_mob                  # kill_mob / submit_item

# ---- 导航目标（可选）：SoulCore Fabric 客户端在此渲染导航光柱 ----
# navigate: "world,100,64,200"   # 世界名,x,y,z

# ---- 任务追踪完全自定义（可选，留空 = 使用插件内置默认格式） ----
# board-title: "&6&l{name}"    # 变量 {name} {id} {type}
# board-line:                   # 任意多行；{target1}/{current1}/{total1} 等为第 1 个目标变量
#   - "&7目标1：击杀 &f{display1} &e{current1}&7/&e{total1}"
#   - "&7目标2：击杀 &f{display2} &e{current2}&7/&e{total2}"
#   - "&7总进度：&e{current}&7/&e{total}"

# ---- 多项目标（推荐写法） ----
objectives:
  - mob: SkeletonKing           # MythicMobs 怪物内部名
    amount: 10                 # 击杀数量
    name: "&7骷髅王"            # 自定义显示名（可选）
    # board-line: "&c击杀 {target} &e{current}&7/&e{total}"  # 该目标行（可选，留空 = 用内置默认格式）
  - mob: ZombieMinion
    amount: 5
    name: "&2僵尸小兵"
# ---- 单目标简写（与 objectives 二选一，objectives 优先） ----
# mob: SkeletonKing
# amount: 10

condition-commands:                 # 每次接取最多执行一次
  - "message &a你已达成任务条件：&f%quest_name%"
  - "cq data set %player% 5 stage kill_ready"

repeatable: false              # 是否可重复
cooldown: 3600                 # 重复接取冷却（秒）

类型二：提交物品（submit_item，多种物品）

quest-id: example_submit
type: submit_item

# 写法一：items 列表（材料:数量）
items:
  - "DIAMOND:5"
  - "IRON_INGOT:10"

# 写法二：objectives 列表（推荐，支持更多自定义）
#   name       自定义显示名（计分板/提示显示用）
#   item-name  可选：只收集显示名为该文字的物品（铁砧改名）
#   board-line 可选：该目标在计分板上的显示行（留空 = 用内置默认格式）
# objectives:
#   - item: "DIAMOND:5"
#     name: "&b大钻石"
#     item-name: "&b大钻石"
#     board-line: "&b收集 {target} &e{current}&7/&e{total}"
#   - item: "IRON_INGOT:10"
#     name: "&f铁锭"

condition-commands:
  - "message &a你已达成任务条件：&f%quest_name%"

condition-commands 未配置 message 时发送默认达成提示；配置 message 后会替换默认提示。 message <文本> 发送聊天消息，其他内容作为控制台指令执行。 支持 %player%、%quest%/%quest_id%、%quest_name% 和 PAPI。 击杀任务在目标达成时执行；物品任务只在 NPC 校验并扣物成功后执行。 达成标记随玩家任务进度持久化，同一次接取即使重新登录或重启也不会重复触发。 旧 auto-complete、任务级 commands 和任务级 kether 已删除并忽略。

类型三：描述任务（describe，展示型）

无任何目标，用于在全息视图（计分板）上展示任务标题与内容；只能通过指令强制完成。 

quest-id: describe_story
name: "&6&l主线剧情"          # 任务标题（计分板首行）
# board-title: "&d&l{name}"    # 可选：标题行格式（留空 = 用内置默认格式）
description:                     # 任务内容（计分板逐行展示）
  - "&7第一章 · 初入荒野"
  - "&7找老杰克聊聊吧"
type: describe                 # 描述任务（无目标）

# 显示（接取）：/cq quest accept <玩家> describe_story
#            （或对话选项 accept-quest / Kether quest accept）
# 完成（从计分板移除）：/cq quest complete <玩家> describe_story
# 注意：Kether 的 quest complete / quest submit 对描述任务无效，仅指令可完成

分支门控条件写法（NPC 对话）

接取任务不校验前置条件。任务门控（谁能看到并点击接取选项）由 NPC 对话分支条件控制：

PAPI 条件（papi）

写法含义
%player_level% >= 10数值比较（支持 >= <= > <）
%var% == 值 / !=相等 / 不相等
%var% contains 文本 / !contains包含 / 不包含
%var%单独占位符：值为 true/yes/1 或非空且非 false/no/0 为真
!%var%取反

NPC data 条件（data / data-value）

写法含义
stage该 data 变量存在
stage==none等于（支持 !=）
level>=1 / <3数值比较
NPC data 是玩家级数据：每个玩家在同一 NPC 上有自己独立的 data 值（持久化保存）， 因此不同玩家会看到不同的对话分支；管理员可用 /cq data set <玩家> <npcId> <key> <value> 手动管理。
例如：分支 A 的 data: stage / data-value: none 只在该玩家的 data「stage」为 none 时显示， 玩家点击其中的接取选项后通过 accept-data: "stage=kill_doing" 将其改为 kill_doing， 该玩家下次点击 NPC 就会进入任务进行中的分支——分支任务 / 分支对话由此驱动。

NPC 对话配置 dialogues/

每个文件通过 npc: <id> 绑定 Citizens NPC（可写列表 [5, 6]）。 玩家点击 NPC 后，从上到下查找第一个「条件全部满足」的分支显示；带条件的分支都不满足时， 回退到 default: true 或无条件的分支。 

npc: 5                        # 绑定 NPC id
title: "&8[&6任务发布官&8] &f老杰克"

# 首次对话初始化（可选，推荐）：玩家第一次点击该 NPC 时，
# 若某个 data 变量不存在则自动写入默认值（玩家级），
# 让 data: stage / data-value: none 这类初始分支条件第一次就能生效
default-data:
  stage: none

branches:
  all_done:                    # PAPI 完成分支必须放在 data 分支之前
    papi:
      - "%customquest_done_example_submit% == true"
    lines: ["&f感谢你的帮助！"]

  kill_done_offer:             # 击杀完成后提供物品任务
    papi:
      - "%customquest_done_example_kill% == true"
      - "%customquest_done_example_submit% == false"
      - "%customquest_has_example_submit% == false"
    lines: ["&f还需要一些矿物，你愿意帮我收集吗？"]
    options:
      accept:
        text: "&a&l[接受收集任务]"
        accept-quest: example_submit
        accept-data: "stage=item_collecting"

  initial:                     # 会话绑定的稳定分支 ID
    data: stage               # NPC data 条件（写法一：key + data-value）
    data-value: none
    # 或列表写法（写法二）：data: ["stage==none", "level>=1"]
    papi:                      # PAPI 条件（可选）
      - "%player_level% >= 3"
    lines:                     # 对话内容
      - "&f你好，旅行者！我这里有件麻烦事……"
    options:                   # 可点击选项
      accept:
        text: "&a&l[接受任务] &a清剿荒野"
        hover: "&7点击接受任务"       # 悬浮提示（可选）
        # ---- 接取任务快捷指令（推荐） ----
        accept-quest: example_kill   # 点击后接取任务（不校验前置条件）
        accept-data: "stage=kill_doing"   # 接取成功后设置 NPC data 变量
        # 等价 Kether 写法：
        # kether:
        #   - "quest accept example_kill data stage kill_doing"
      reject:
        text: "&7我暂时没空"
        kether:
          - "npc data set stage none"

  kill_doing:
    data: stage
    data-value: kill_doing
    lines: ["&f怪物清剿得如何了？"]

  kill_ready:
    data: stage
    data-value: kill_ready
    lines:
      - "&a你已经达成任务条件。"
    options:
      submit:
        text: "&a&l[提交击杀任务]"
        submit-quest: example_kill

  item_collecting:
    data: stage
    data-value: item_collecting
    lines: ["&f把要求的物品放在主背包后交给我。"]
    options:
      submit:
        text: "&a&l[提交物品]"
        submit-quest: example_submit
        submit-items:                 # 可选；不写则沿用任务 objectives/items
          - item: DIAMOND
            amount: 5
            name: "&b大钻石"
            item-name: "&b大钻石"
          - "IRON_INGOT:10"

  fallback:
    default: true            # 兜底分支（可选）
    lines: ["&f……"]
    options:
      leave:
        text: "&7离开"
        kether: []

分支对话流程图（data 驱动）

玩家点击 NPC #5
   │
   ├─ initial ─────────► accept example_kill ─► stage=kill_doing
   ├─ kill_doing ──────► 击杀目标达成 ────────► condition-commands 设置 kill_ready
   ├─ kill_ready ──────► submit example_kill ─► 写入击杀任务完成状态
   ├─ kill_done_offer ─► accept example_submit ► stage=item_collecting
   ├─ item_collecting ─► 校验并扣除 submit-items ► 写入物品任务完成状态
   └─ all_done ────────► 完成对话
  • SoulCore 对话 UI 与聊天回退共用绑定玩家的一次性会话；执行时会再次校验分支条件、NPC 状态和交互距离；
  • accept-quest 接取任务不校验前置条件；只有接取成功才写入 accept-data 并继续选项 Kether；
  • submit-quest 只在进度足够时成功；物品任务会原子扣物并列出全部缺少项，成功后完成任务但不修改 NPC data；
  • submit-items 必须与 submit-quest 同时使用，仅支持 submit_item；任务原目标与覆盖清单都会校验，实际只扣覆盖清单；
  • 映射写法支持 item: DIAMOND + amount: 5，以及可选 name/item-name；空列表、空气、未知材料和非正整数会拒绝加载；
  • 任一物品不足时零扣除、零完成；两份清单的缺口按多重集合合并，同规格保留更大实际缺口后全部提示；
  • 选项 Kether 执行时注入变量：@NpcId、@BranchId、@Option、@OptionId、@Player；
  • 单次最多 8 行、6 个选项、8192 bytes；选项 ID 必须为 1–64 UTF-8 bytes 且不能包含控制字符；
  • NPC data 为玩家级数据：每个玩家在该 NPC 上有独立 data 值（持久化保存），不同玩家处于不同对话分支； 管理指令需指定玩家：/cq data set <玩家> 5 stage none；
  • data 变量为 持久化 存储，服务器重启后不丢失。

动作说明

常见问题

1. 首次启动卡在「正在下载依赖」？

TabooLib 运行时模块需要从 repo.tabooproject.org 下载一次（约 10~20MB），完成后缓存于 服务器根目录的 libraries 文件夹，之后可离线启动。

1.1 服务器无法访问 repo.tabooproject.org（UnknownHostException / 连接超时）？

这是服务器网络（DNS）无法解析 TabooLib 依赖仓库导致的，报错为：

UnknownHostException: repo.tabooproject.org / sacredcraft.cn
无法初始化原始加载器
无法启动 Kotlin 环境。(未能找到 kotlin2021.Lazy)

解决办法：在可联网构建机执行 ./gradlew collectLibs --console=plain，然后：

  1. 保持 Maven 目录结构，将 offline-libs/ 的内容复制到服务器根目录 libraries/；
  2. 单独安装 CustomQuest、PlaceholderAPI，以及按需使用的 MythicMobs/Citizens；
  3. 删除旧版插件 jar 后重启服务器。

插件检测到依赖已存在时会跳过下载直接加载，服务器全程无需联网。

2. Citizens 提示「Error occurred while enabling Citizens」？

请使用与 Paper 1.21.x 匹配的 Citizens 版本（2.0.36 以上新构建），本插件对 Citizens 采用软依赖，Citizens 异常不影响本插件其他功能。

3. 任务能接取但击杀不计数？

请确认任务配置中的 mob 与 MythicMobs 怪物内部名完全一致（大小写不敏感），且击杀者是玩家本人。

4. 点击对话选项没反应？

请确认玩家未被聊天拦截类插件屏蔽 run_command 点击事件，且 /cq 指令未被其他插件占用。

5. 计分板不显示？

检查 scoreboard.enabled 是否为 true 并执行 /cq reload。支持 SoulCore 通道时任务会显示在 HUD； 无客户端通道才使用原生计分板回退。检测到其他插件已占用侧边栏时 CustomQuest 会主动让出，不会覆盖或反复抢占。
